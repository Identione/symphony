## 2. Orchestrator state machine

`SymphonyElixir.Orchestrator` is a GenServer whose `State` struct tracks issues across the sets `running`, `completed`, `claimed`, `blocked`, and `dependency_blocked`, plus bookkeeping maps (`retry_attempts`, `deterministic_failures`, `pending_escalations`, `session_counts`, …). An issue's lifecycle is: candidate → dispatched (`running`) → on turn-exit either a normal-exit continuation retry or an abnormal-exit retry/backoff/block/escalate → terminal cleanup. Running every poll cycle alongside that are reconciliation against live Linear state, stall detection/restart, dependency pause/resume, and parent auto-completion.

## 7. Workspace safety

Two enforcement layers exist: `PathSafety.canonicalize/1` resolves a path's real, symlink-free location, and `Workspace` (with a duplicate check in `Codex.AppServer`) uses that canonical form to prove a workspace both lives under `workspace.root` and is not the root itself, rejecting anything that resolves outside it (including via symlink escape). For remote (SSH) workers, canonicalization is impossible, so the invariant is enforced with a weaker lexical prefix/dot-segment check plus a control-character check.
